▶ Migration Checklist — Existing Case → Waypoint Origin Shape
  1. Bootstrap — waypoint firmvault bootstrap --cases-root /path --case-name "..." --case-type personal-injury --start --json
  2. Copy materials — move existing PDFs, scans, letters into the canonical folders above (keep originals read-only until verified)
  3. Create evidence stubs — one evidence/*.md file per major lifecycle fact; short summaries pointing to real document paths
  4. Validate paths — waypoint firmvault evidence check --path evidence/client-intake.md --json (must be relative, inside case folder, existing, no traversal)
  5. Record facts — waypoint firmvault state set --fact client.intake --status complete --evidence evidence/client-intake.md --note "Mapped from legacy folder."
  6. Check landmarks — waypoint firmvault landmarks --json → track satisfied: true count (target: 82/82)
  7. Never edit .waypoint/firmvault/*.yaml directly — the CLI is the only safe mutation path
▶ What Waypoint Tracks vs. What It Doesn't
Waypoint owns: lifecycle state in YAML, landmark projection (computed booleans), evidence paths, audit events (JSONL), recipe execution, task gating.

Waypoint does NOT own: OCR, PDF splitting, document naming, Forgejo PRs, email/fax, trust-account transfers. Those live in firmvault-document-pipeline (separate Python repo). Pipeline status is tracked as metadata in .waypoint/firmvault/documents.yaml — it never satisfies legal landmarks by itself.

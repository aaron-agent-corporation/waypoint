# Referral Package Local Runtime + Blocker Resolution Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Make the Waypoint `referral-package` Quest capable of running a real local package-builder runtime, blocking on unresolved/missing medical chronology artifacts, recording non-chronology legal blockers as transfer/QC notes, and resuming the same Quest route after a human/agent resolves a blocker.

**Architecture:** Add a narrow first-party local recipe runtime adapter that consumes the existing F10 stdin payload and handles the referral-package recipe slugs deterministically inside the case folder. Add a generic blocked-task resolution primitive/CLI command that re-checks required artifacts and reopens the blocked task so `waypoint auto` resumes from the actual blocked node instead of skipping it. Keep human attorney handoff as a gate.

**Tech Stack:** TypeScript, Node ESM, existing `@waypoint/folder-host` local runtime payload, YAML/JSONL route/task stores, Vitest.

---

## Product semantics

- `runtime.recipe: null` remains a safe simulation mode, but artifact-producing tasks with declared `metadata.waypoint.output_artifacts` must not advance unless those artifacts exist.
- `runtime.recipe: local` plus a configured command should execute a real local builder command.
- The referral-package local builder is conservative:
  - source folders remain read-only;
  - no external side effects;
  - non-medical legal blockers are written into transfer/QC outputs as unresolved issues, not treated as fatal runtime blockers;
  - medical chronology artifacts remain required when the Quest declares them; if not present after the chronology recipe, the route blocks at the chronology task;
  - final attorney-facing handoff still requires a human gate.
- When a route blocks and Aaron/the paralegal resolves the blocker, Waypoint needs an explicit operator input to record the resolution and reopen the blocked task. Then `waypoint auto` resumes the route from that task.

## Task 2 — GREEN: implement first-party local referral-package builder command

**Objective:** Implement the minimal local adapter behind `waypoint runtime referral-package-builder`.

**Files:**
- Create: `packages/waypoint-folder-host/src/runtime/referral-package-builder.ts`
- Modify: `packages/waypoint-folder-host/src/index.ts`
- Create: `packages/waypoint-cli/src/commands/runtime.ts`
- Modify: `packages/waypoint-cli/src/bin.ts`

**Behavior:**
- Read the existing local runtime stdin payload.
- Support these recipe slugs:
  - `firmvault-medical-chronology-update`: do not fabricate chronology; return success only if declared/expected chronology artifacts already exist, otherwise exit non-zero with a clear message so autopilot blocks/fails before downstream package generation.
  - `firmvault-medical-chronology-adversarial-qc`: require `adversarial-qc-report.md` if chronology QC has not been generated by a real chronology process; do not fabricate final QC.
  - `referral-package-start-here-builder`: write a conservative `START_HERE.html` and small `START_HERE.pdf` placeholder/review aid only from available source/file inventory and unresolved blocker notes.
  - `referral-package-package-qc`: write `package-qc-report.json` with `determination: blocked_not_attorney_ready` when unresolved legal/medical issues are present, while still satisfying the artifact requirement so the route can reach the human gate.
- Write package index artifacts for `package-index` checkpoint/recipe support when appropriate.
- Do not mutate `.waypoint/firmvault` legal state.

**GREEN command:**
`pnpm exec vitest run packages/waypoint-folder-host/src/autopilot/run.test.ts -t "referral package local builder"`

## Task 3 — RED/GREEN: blocked-task resolution primitive

**Objective:** Add an explicit Quest input for resolved blockers so the route can resume from the blocked task.

**Files:**
- Modify test: `packages/waypoint-folder-host/src/routes/state.test.ts`
- Modify: `packages/waypoint-folder-host/src/routes/state.ts`
- Modify: `packages/waypoint-folder-host/src/index.ts`
- Create: `packages/waypoint-cli/src/commands/resolve.ts`
- Modify: `packages/waypoint-cli/src/bin.ts`

**Behavior:**
- Add `resolveWaypointRouteBlocker(projectRoot, { routeId, taskId?, note })`.
- If `taskId` omitted, resolve the currently blocked route node's blocked task.
- If task metadata has `block_reason: required_artifacts_missing`, re-check the task's declared output artifacts. If any are still missing, throw and keep it blocked.
- If artifacts are present, clear `missing_artifacts`/`block_reason`, set task status back to `open`, set route status `active`, set `current_node` to the task plan ref, and append `route.blocker.resolved` with the note.
- CLI: `waypoint resolve --route-id <id> [--task-id <id>] --note <text> [--json]`.
- After resolving, a subsequent `waypoint auto --route-id <id>` reruns the reopened task and continues.

**RED command:**
`pnpm exec vitest run packages/waypoint-folder-host/src/routes/state.test.ts -t "resolves required artifact blockers"`
